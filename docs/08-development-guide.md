# 08. Руководство разработчика

## 8.1. Инструменты

| Инструмент | Версия (минимум) | Примечание |
|------------|------------------|------------|
| GCC | 12.2 (Debian 12) | Основной компилятор Linux |
| Clang | 14 | clang-tidy, clang-format, clangd |
| MSVC | 2022 17.6+ | Windows |

| Qt | 6.4 | Widgets (+ OpenGLWidgets — этап 2) |

### Ограничения C++23 на GCC 12

Стандарт — C++23, но используется только то, что поддерживают **все** целевые компиляторы:

| Можно | Нельзя (пока) |
|-------|---------------|
| `std::expected`, `std::span`, концепты, `constexpr`-алгоритмы, `std::ranges` (базово), `std::atomic<std::shared_ptr>` | `std::format` (GCC 13), `std::print` (GCC 14), deducing this (GCC 14), `std::mdspan`, модули C++20 |

`std::format` в libstdc++ появился только в GCC 13. На GCC 12 — использовать `fmt` (идёт вместе со spdlog)
через тонкую обёртку `mrs::format`. Решение пересмотреть при переходе на GCC 13+ (Q-010).

## 8.2. Зависимости

## 8.3. Сборка

```bash
cmake --preset debug
cmake --build --preset debug
ctest --preset debug
```

Пресеты (`CMakePresets.json`):

| Пресет | Назначение |
|--------|------------|
| `debug` | -O0 -g, ассерты, предупреждения как ошибки |
| `release` | -O2, без ассертов ядра (кроме критических) |
| `asan` | AddressSanitizer + UBSan |
| `tsan` | ThreadSanitizer (проверка обмена потоков) |
| `headless` | Только `core/domain/training/infrastructure` + тесты — без Qt (CI-проверка NFR-MNT-001) |

Флаги предупреждений: `-Wall -Wextra -Wpedantic -Wconversion -Wshadow -Werror` (MSVC: `/W4 /WX`).
`-ffast-math` запрещён (детерминизм).

`build/` и `.cache/` — в `.gitignore`.

## 8.4. Стиль кода

* Форматирование — `.clang-format` (основа: LLVM, отступ 4, ширина 110, фигурные скобки — Allman, как
  в текущем коде).
* Имена: типы `PascalCase`, функции и переменные `camelCase`, члены `camelCase_`, константы `kCamelCase`,
  пространства имён `mrs::domain::radar` (`snake_case`), файлы `snake_case.h/.cpp`.
* Заголовки — `#pragma once`.
* Владение: значения и `std::unique_ptr`; сырые указатели — только невладеющие (и Qt parent-ownership в UI).
* В domain — без исключений в горячем пути, без глобального состояния, без синглтонов.
* Физические величины — только через строгие типы `core/units.h`.
* Комментарии — «почему», а не «что»; формулы — со ссылкой на раздел [03-domain-radar-model.md](03-domain-radar-model.md).

## 8.5. Тестирование

| Уровень | Что | Инструмент |
|---------|-----|------------|
| Unit | core (единицы, углы, проекция), ДКС/ВКС/ДПК/ВПК, фильтр Калмана, модели движения, генерация спицы, критерии оценивания, форматирование | GoogleTest |
| Property | Инварианты: пеленг ∈ [0, 2π), ДКС ≥ 0, ДКС ≤ текущей дальности при ВКС > 0 | GoogleTest + параметризация |
| Golden | Спица/оборот видео при фиксированном seed совпадает с эталоном (хэш) | GoogleTest |
| Integration | Загрузка всех сценариев; прогон 10 мин сценария headless; детерминизм (2 прогона = одинаковые хэши) | `mrs_headless`, ctest |
| Performance | Генерация оборота, построение LUT, кадр ИКО | Google Benchmark |
| UI (ручное) | Чек-лист приёмки по этапу | `docs/checklists/` |

Эталонные случаи для САРП (обязательно):

* Встречный курс на одной линии → ДКС = 0, ВКС = D / (V1+V2).
* Параллельные курсы, одинаковая скорость → |v| = 0 → ДКС/ВКС «не определено».
* Цель за кормой догоняет → ДПК < 0 или нет пересечения.
* Переход пеленга через 0°/360° при сопровождении.

## 8.6. Git

* Ветки: `main` — всегда собирается и проходит тесты; `feature/<кратко>` — работа; слияние через PR.
* Коммиты: `<область>: <что сделано>` — `radar: sea clutter STC model`, `ui: PPI LUT rendering`, `docs: …`.
* PR: описание, ссылки на ID требований (`FR-TT-008`), чек-лист (тесты, документация, clang-tidy).
* В PR, меняющем поведение, обновляется соответствующий документ в `docs/`.

## 8.7. CI (когда появится удалённый репозиторий)

1. `headless` — сборка без Qt + тесты (NFR-MNT-001).
2. `debug` Linux GCC + тесты.
3. `asan`/`tsan` — ночная сборка.
4. clang-format --dry-run, clang-tidy.
5. `mrs_headless --validate data/`.
6. Windows MSVC — сборка + тесты.
7. Release-артефакт: архив / установщик (`windeployqt`, AppImage или .deb).

## 8.8. Definition of Done (для любой задачи)

* Код собирается всеми пресетами, предупреждений нет.
* Тесты добавлены/обновлены, проходят.
* Документация обновлена (требования, модель, архитектура — что затронуто).
* Нет зависимости domain/training от Qt.
* Проверено вручную в приложении (для UI-задач — скриншот в PR).
