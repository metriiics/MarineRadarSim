# 07. Обучение и оценивание

## 7.1. Модель учебного процесса

```text
Каталог заданий ─► Задание (task) ─► Сеанс (session) ─► Отчёт (report)
                       │                  │
                       ▼                  ▼
                 Сценарий (scenario)   Запись (recording) → разбор (replay)
```

* **Задание** — что надо сделать и как это проверить.
* **Сеанс** — одно выполнение задания конкретным обучаемым.
* **Оценивание** — наблюдатель: читает снимки, события и команды; **никогда не меняет** мир
  (единственное исключение — завершение сеанса по лимиту времени через `SessionController`).

## 7.2. Уровни и примерный каталог заданий

| Уровень | Задание | Проверяемые навыки |
|---------|---------|--------------------|
| basic | Включение РЛС и подготовка к работе | Последовательность ВЫКЛ→ГОТОВ→ИЗЛУЧ., ожидание прогрева |
| basic | Настройка изображения | УСИЛЕНИЕ, АПЧ, выбор шкалы |
| basic | Борьба с помехами моря и дождя | ВОД/ДОЖДЬ без потери малых целей |
| basic | Измерение пеленга и дальности | ЭВН/ПКД, точность |
| intermediate | Ручной захват и сопровождение | Захват, чтение данных цели |
| intermediate | Определение опасной цели | ДКС/ВКС, настройка пределов |
| intermediate | Режимы ориентации и движения | Север/Курс/Нос, ОД/ИД, интерпретация векторов |
| intermediate | Определение места по РЛ-ориентирам | Пеленг/дальность на берег, буй |
| advanced | Расхождение с использованием проигрывания манёвра | Trial manoeuvre, выбор манёвра по МППСС |
| advanced | Работа при отказе гирокомпаса | Распознавание, переход в «Нос», ограничения САРП |
| advanced | Обмен целей / потеря цели | Обнаружение ошибки сопровождения |

## 7.3. Типы критериев

| Тип | Смысл | Параметры |
|-----|-------|-----------|
| `state` | Предикат над снимком стал истинным | `condition`, `within_s` (опц.), `hold_s` (держать N с) |
| `sequence` | Действия выполнены в заданном порядке | Список шагов (команд/состояний), допускаются ли лишние действия |
| `accuracy` | Измерение оператора в допуске | Что измеряется (пеленг ЭВН на цель X), допуск |
| `answer` | Ответ обучаемого (выбор цели/варианта в окне задания) | `expected` |
| `forbidden` | Недопустимое состояние/действие | `condition`, `max_duration_s`, `penalty` |
| `time_limit` | Задание выполнено в срок | `time_limit_s` |
| `outcome` | Итог ситуации | Например: «ДКС с любой целью ≥ 1 мили всё время сеанса» |

### Реестр предикатов

Условия — именованные C++-функции, регистрируемые в `PredicateRegistry`:

```cpp
registry.add("radar.power", [](const Snapshot& s, const Args&) { return toString(s.radar.power); });
registry.add("tracked_all_within",
    [](const Snapshot& s, const Args& a) { return allTruthTargetsTracked(s, a.get<Meters>("range")); });
registry.add("min_cpa_truth", [](const Snapshot& s, const Args&) { return minTrueCpa(s); });
```

Почему не скриптовый язык: MVP проще тестировать, ошибки ловятся на загрузке, нет зависимостей.
Если предикатов станет много и методисты захотят писать свои — ADR на встраивание Lua (этап 3+).

### Истинное состояние против индикации

Критерии могут обращаться к `GroundTruthView` (что есть на самом деле) и к индикации (что видит
оператор). Пример: «цель взята на сопровождение» = существует трек, ассоциированный с истинной целью
(ближайшая истинная цель в пределах ворот на протяжении ≥ 3 обзоров).

## 7.4. Оценка

```
score = Σ(weight_i · result_i) / Σ weight_i − Σ penalty_j / Σ weight_i,    0 ≤ score ≤ 1
result_i ∈ {0, 1} или частичный (accuracy: линейно от допуска до 2·допуска)
passed = score ≥ passing_score и нет критериев с флагом critical: true, имеющих статус failed
```

Статусы критерия: `pending → passed | failed | violated`. Каждое изменение статуса — событие в журнале
сеанса с временем.

## 7.5. Режимы

| | Обучение (training) | Контроль (exam) |
|---|---|---|
| Подсказки | Да (−10 % за подсказку) | Нет |
| Пауза | Да | Нет (только инструктор) |
| Ускорение времени | По заданию | Нет |
| Показ истинных целей | Через меню инструктора | Нет |
| Прогресс по критериям | Виден | Только итог |

## 7.6. Разбор (debriefing)

Запись сеанса воспроизводится с той же скоростью или ускоренно; на временной шкале — отметки событий
и изменений статусов критериев. Режим «показать истинные цели» в разборе доступен всегда.
