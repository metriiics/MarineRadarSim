# 05. Интерфейс оператора

## 5.1. Принципы

* Экран воспроизводит рабочее место оригинальной РЛС: расположение, названия, порядок действий.
  Источник истины — руководство оператора оригинала (Q-002); до его получения — текущий макет
  (`src/presentation/main_window/main_window.cpp`).
* Управление — мышью (как трекбол оригинала) + горячие клавиши для органов, которые на оригинале
  физические (регуляторы).
* UI **не вычисляет** ничего, кроме экранной геометрии и форматирования. Значения ДКС/ВКС, пеленги,
  координаты курсора приходят из снимка или из `ScreenGeometry` (application).

## 5.2. Компоновка экрана (реализовано)

Целевой экран — **1280×1024 (5:4)**. Круг ИКО — главный элемент: занимает всю высоту, левым
краем у левой границы экрана, правым — вплотную к колонке данных. Остальные блоки компактно
лежат «лесенкой» в четырёх углах квадрата вокруг круга и не заходят на шкалу. Набор и
назначение блоков — по эскизу оператора.

```text
┌ MarineRadarSim ─────────────────────────────────────── [⚙][–][□][×] ┐
│УСИЛЕН.[▌] ИЗЛУЧ.│ВКЛ       0   1.5 /0.25 МИЛЬ│ курс гиро  170.0 °  │
│ВОЛНЫ [█]        340 · · · · · 20      КУРС   │ ск лаг (в)   0.0 уз │
│ДОЖДЬ [▌]      ·                ·      ОД     │ широта / долгота    │
│АПЧ   [█]    ·                    ·    ВОДА   │ [                 ] │
│[_┌┐_]      ·          │             ·  СК-42 │ (UTC) время         │
│Х-ДИАП     ·      линия курса         · дата  │ данные цели САРП    │
│ИПЗ       ·                            ·[ ][ ]│ …                   │
│     270 ·          (чёрный)            · 90  │ (сообщения)         │
│          ·                            ·      │                     │
│           ·                          ·  ЛОД  │ СЛЕДЫ / пороги      │
│┌────────┐   ·                      ·   САРП  │ курсор              │
││ВН КУ37.1│        200 · · · 160         ВД   │                     │
└┴────────┴─────────────180──────────────────┴─────────────────────┘
       круг ИКО 960 px (по ширине)               колонка данных 300 px
```

Цвета (`src/presentation/theme/theme.h`):

| Элемент | Цвет |
|---------|------|
| Фон, в том числе внутри круга ИКО | чёрный |
| Линия курса | белый |
| Шкала пеленгов ИКО (риски) | зелёный |
| Цифры шкалы пеленгов | жёлтый |
| Рамки блоков | жёлтый |
| Надписи и единицы измерения | синий |
| Числовые значения | жёлтый |
| Заполнение шкал регуляторов, индикатор настройки | зелёный |

Сетка размеров (`theme.h`): высота однострочного блока 28 px, шрифт 14 px, отступ между блоками
2 px (везде одинаковый — строки угловых стопок совпадают с блоками колонки), внутренний отступ 8 px.
Текст в блоках — прописными буквами.

Терминология оператора (важно при правках по замечаниям):
* у блока «длина» — горизонтальная сторона, «ширина» — вертикальная;
* «вертикальное расстояние» — зазор между блоками, стоящими **рядом** (`| |`);
* «горизонтальное расстояние» — зазор между блоками **друг над другом** (`_` над `_`).

Геометрия (`MainWindow::layoutWorkstation`, `PpiWidget`):
* Колонка данных — 300 px, все блоки по её ширине, блоки друг над другом — через 2 px; зазор
  между колонкой и блоками у круга (стоят рядом) — 8 px. Часы UTC — по центру колонки.
  Верх колонки согласован со стопкой у круга: КУРС ГИРО чуть выше шкалы дальности (46 и 40 px),
  ШИРОТА/ДОЛГОТА той же высоты, что КУРС ГИРО; низ ОД — чуть выше низа ШИРОТЫ/ДОЛГОТЫ; строка
  UTC — вровень с датой и той же высоты, перед временем — значок часов (круг со стрелками),
  пустой блок над строкой добирает разницу.
* СК-42 и дата растягиваются по высоте так, что под датой через обычный зазор 2 px стоят малые
  индикаторы, а их верх совпадает с верхом данных цели; UTC заканчивается в 2 px над данными цели.
  Блок данных цели при этом не меняется (`MainWindow::alignBlocksToScale`).
* Данные цели (ВСЕГО ЦЕЛЕЙ САРП…): верх — на уровне цифры 50 шкалы, низ — чуть выше отметки 90°;
  после заголовка «ВСЕГО ЦЕЛЕЙ САРП» — пустая строка;
  строки плотные, свободное место — внизу блока.
* Блок сообщений — вплотную под данными цели, низ — чуть ниже цифры 120 шкалы (на 12 px ниже её
  нижнего края); свободное место колонки и отступ 30 px — под ним, до СЛЕДОВ
  (`MainWindow::alignBlocksToScale`).
* СЛЕДЫ/точки и курсор — с плотными строками; курсор по высоте равен двум блокам ВД. ВД стоит
  напротив нижней половины курсора, САРП — от его верхней границы и чуть не доходит до половины;
  ЛОД той же высоты, что САРП, заканчивается на уровне низа СЛЕДОВ.
* Область ИКО — круг плюс полоса до 10 px слева под угловые
  блоки; круг прижат к правому краю области, то есть вплотную к колонке данных. На широком
  мониторе (16:9) композиция центрируется.
  При колонке 300 px на экране 1280×1024 круг ограничен шириной: 960 px вместо 980 по высоте.
* Шкала пеленгов: окружность не рисуется сплошной линией — её образуют риски снаружи рабочей
  области: малые через 1°, средние через 5° (без цифр), большие через 10° с подписями 0…350.
* Угловые стопки: каждая следующая строка уже предыдущей и повторяет изгиб шкалы. Длины блоков,
  привязанных к цифрам шкалы (регуляторы, ИЗЛУЧЕНИЕ, Х-ДИАП, ВН, шкала дальности), вычисляются из
  положения этих цифр (`PpiWidget::bearingLabelRect`, `bearingLabelDigitRect`,
  `MainWindow::alignBlocksToScale`).
* Круг уменьшается из-за наложенных блоков, только если блок задевает риски или прямоугольник
  цифры; блок над цифрой (а не на ней) круг не уменьшает. Ширины
  рассчитаны для квадрата 980 px (экран 1280×1024 с заголовком окна). Если квадрат меньше, круг
  уменьшается ровно настолько, чтобы не заходить под блоки (`PpiWidget::setReservedAreas`).

| Угол | Блоки (сверху вниз / снизу вверх) |
|------|-----------------------------------|
| Верхний левый | высота строк подбирается по шкале: низ АПЧ — прямо над цифрой 320, низ Х-ДИАП — прямо над 310 (≈27 px при 1280×1024). Регуляторы УСИЛЕНИЕ, ВОЛНЫ, ДОЖДЬ, АПЧ — каждый один блок «название │ зелёная шкала»; правый край АПЧ — над серединой цифры «3» в 320. | Нижний левый | ВН / КУ — правая граница под цифрой 220 шкалы, чуть не доходя до её центра (считается от положения цифры) |
| Верхний правый | Шкала дальности (высота 40 px, левая граница на 30 px левее центра цифры 30; крупная «1.5» почти во всю высоту блока; «0.25» стоит над цифрой «0» отметки 40), КУРС, ОД, ВОДА (левый край — над серединой цифры «5» отметки 50, текст по центру), СК-42 и дата (по 86 px, текст по центру, по высоте — до малых индикаторов); КУРС/ОД/ВОДА по 24 px; два малых индикатора — верхней границей на уровне верха блока «ВСЕГО ЦЕЛЕЙ САРП» |

## 5.3. ИКО (PPI) — состав слоёв

Рисуется снизу вверх:

1. Фон (цвет экрана, режим день/ночь).
2. **Радиолокационное видео** с послесвечением (из полярного растра).
3. Кольца дальности, шкала пеленгов по краю (0…359°, метки 1°/5°/10°).
4. Отметка курса (линия курса), отметка севера.
5. ЭВН (пунктир), ПКД (окружность), параллельные индексы.
6. Зоны охраны.
7. Символы САРП: захватываемая цель (пунктирный квадрат/круг), сопровождаемая (круг), опасная (мигающий
   треугольник), потерянная (ромб); векторы; прошлые позиции; номер цели.
8. Курсор (перекрестие).
9. Служебные надписи на поле ИКО (шкала, кольца, ориентация, режим движения) — если они есть на оригинале.

Символика САРП — по IEC 62288 (символы на навигационных дисплеях), уточнить по оригиналу.

## 5.4. Отрисовка видео

### Данные

* `PolarRaster video` — `uint8[N_az][N_r]`, амплитуда.
* `PolarRaster age` — время последнего обновления спицы (`float` на спицу, а не на ячейку).
* Новые спицы из `SpokeChannel` копируются в `video` построчно.

### Кадр (MVP, CPU)

```text
LUT[pixel] = (spokeIndex, rangeBin) | INVALID     // пересчёт при resize / ориентации / off-centre / шкале
for pixel in ИКО:
    (a, r) = LUT[pixel]
    amp   = video[a][r]
    fade  = afterglow(now − age[a])               // 1 → 0 за время послесвечения
    color = palette[amp] * fade
```

* Ориентация «Север» / «Курс» / «Нос» — это только поворот LUT: спица `a` хранится в истинных
  пеленгах (стабилизация по гирокомпасу), поворот добавляется при построении LUT. При «Нос» без
  стабилизации LUT поворачивается вместе с курсом → изображение «смазывается» при повороте — это верно.
* Истинное движение (ИД): центр развёртки смещается по экрану вместе с собственным судном; при
  достижении границы — автосброс. LUT строится от текущего экранного положения центра.
* 1000 × 1000 пикселей × 60 FPS = 60 млн выборок/с — на CPU реально при простом цикле; запас —
  перерисовывать только при наличии новых спиц или изменениях (30 FPS достаточно, NFR-PERF-001).

### Этап 2: GPU

`QOpenGLWidget`: `video` и `age` — текстуры; фрагментный шейдер: `xy → (r, θ)` → выборка → палитра.
Векторная графика (кольца, САРП) — `QPainter` поверх. Включается конфигурацией, CPU-путь остаётся
как резервный (ADR-0004).

## 5.5. Взаимодействие

| Действие | Ввод | Результат |
|----------|------|-----------|
| Регуляторы УСИЛЕНИЕ/ВОД/ДОЖДЬ | Колесо мыши над регулятором / перетаскивание / клавиши | Команда в ядро, значение на регуляторе |
| Шкала дальности | Кнопки «+»/«−» (или клавиши `PgUp/PgDn`) | `SetRangeScale` |
| Курсор | Движение мыши над ИКО | Локально в UI: пересчёт через `ScreenGeometry`, отображение КУ/Д/φ/λ |
| Захват цели | ЛКМ по ИКО при режиме САРП | `AcquireTarget(world point)` |
| Сброс цели | ПКМ по символу цели → меню | `DropTarget(id)` |
| ЭВН / ПКД | Выбор визира + колесо / перетаскивание | `SetEbl`, `SetVrm` |
| Квитирование тревоги | Кнопка тревоги / клавиша | `AcknowledgeAlarm` |

Каждое действие формирует **команду**, UI не меняет своё отображение до прихода нового снимка
(кроме курсора — он чисто экранный). Так индикация всегда отражает реальное состояние модели.

## 5.6. Окна и режимы приложения

```text
Стартовое окно ──► Выбор задания ──► Брифинг (текст задания) ──► Рабочее место ──► Итоговый отчёт
                                                                     │
                                       Меню инструктора (Ctrl+Shift+I): пауза, ускорение,
                                       показать истинные цели, перезапуск
```

* Режим «обучение»: доступны подсказки и показ истинных целей.
* Режим «контроль»: подсказки и меню инструктора скрыты (защищаются паролем из конфигурации — Q-008).

### Кнопка настроек

На пульте РЛС кнопки настроек нет, поэтому на рабочее поле она не выносится. Окно работает без
системной рамки (`Qt::FramelessWindowHint`) с собственным заголовком `TitleBar`
(`src/presentation/title_bar/`): `[⚙ настройки] [– свернуть] [□ развернуть] [× закрыть]`.

Заголовок отделён от интерфейса только цветом фона, без линии-разделителя.
Перетаскивание и двойной щелчок по заголовку — через `QWindow::startSystemMove()`, изменение размера
за край окна — `startSystemResize()`. Настройки — страница `SettingsPage` на всё окно (вместо
рабочего места; шестерёнка подсвечивается). Слева разделы («Экран», «Управление», «О программе»),
справа содержимое. Возврат — кнопка «НАЗАД», Esc или повторное нажатие шестерёнки. Клавиша
настроек (по умолчанию F10) работает всегда, в том числе в полноэкранном режиме.

### Настройки

Изменения применяются сразу и сохраняются в INI-файл пользователя (`QSettings`):
`~/.config/MarineRadarSim/MarineRadarSim.ini` (Linux), `%APPDATA%\MarineRadarSim\` (Windows).
Модель — `src/presentation/settings/interface_settings.h` (`UiSettings`).

|-----------|----------|--------------|

* Боковые поля — пустые полосы слева и справа от интерфейса РЛС на широком мониторе, за его
  границами (`FillerPanel` без рамки). Пустые блоки внутри интерфейса не оформляются. На экране

  «рыба-глобус» по мотивам логотипа на dalrybvtuz.ru (глобус с параллелями, голова-шеврон с глазом,
  хвост с выемкой, указатели «север — юг») в кольцах сонара, по краям — шкалы с рисками, внизу —
  волны; надписи «ТРЕНАЖЁР СУДОВОЙ РЛС», «ДАЛЬРЫБВТУЗ», полное наименование, «ВЛАДИВОСТОК».
  Цвета — из текущей цветовой схемы (знак и название — цвет цифр с переходом в цвет рамок,
  кольца и подписи — цвет текста, риски — цвет шкалы ИКО).
* Вариант «Логотип (сетка)» (`drawDalrybvtuzGridEmblem`): сетка во всю высоту поля (каждая пятая
  линия ярче), штриховое перекрестие через знак, кольца с рисками как у ИКО, уголки-скобки по
  краям поля; название, наименование и внизу «ВЛАДИВОСТОК 43°07′ С.Ш. 131°53′ В.Д.». Без жёлтого:
  знак и надписи — в тонах цвета текста схемы, линии — цвет шкалы ИКО. Номер варианта в
  настройках — 5 (в конце перечисления, сохранённые настройки не сбиваются).

**Управление**

Таблица действий и клавиш (`keyActions()`): одна клавиша (с модификаторами) на действие,
совпадающие назначения подсвечиваются. Сейчас работают «Открыть настройки» (F10) и
«Полноэкранный режим» (F11); остальные действия (регуляторы, шкала, излучение, визиры, САРП,
квитирование) помечены «позже» — назначения сохраняются, обработчики подключаются вместе с ядром.

## 5.7. ViewModel-слой и форматирование

Все форматы — в одном месте (`presentation/viewmodels/format.h`), с тестами:

| Величина | Формат | Пример |
|----------|--------|--------|
| Пеленг | `ddd.d°` | `037.1°` |
| Курсовой угол | `dd.d ПБ/ЛБ` | `37.1 ПБ` |
| Дальность | `dd.dd` мили (кбт на малых шкалах — по оригиналу) | `2.00` |
| Время | `mm.m` мин | `30.0` |
| Широта | `dd°mm.mmm' N/S` | `43°06.512' N` |
| Долгота | `ddd°mm.mmm' E/W` | `131°53.004' E` |
| Часы | `ЧЧ : ММ : СС` + пояс | `10 : 09 : 44` |

## 5.8. Состояние текущего кода

* Статический экран по эскизу: все блоки, цвета, собственный заголовок с кнопкой настроек.
* Регуляторы УСИЛЕНИЕ/ВОЛНЫ/ДОЖДЬ/АПЧ реагируют на колесо мыши и щелчок по шкале
  (сигнал `valueChanged`, к модели ещё не подключены).
* Часы и дата — системное время (заменить временем сценария после появления ядра).
* Остальные значения — заглушки из эскиза; подключение к `SimulationSnapshot` — этап 1.
