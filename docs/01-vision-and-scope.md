# 01. Видение и границы проекта

## 1.1. Проблема

Подготовка судоводителей к работе с навигационной РЛС/САРП требует доступа к реальной аппаратуре
или дорогому полномасштабному тренажёру. Реальная РЛС на берегу не показывает подвижную обстановку,
а полномасштабный тренажёр доступен ограниченно.

## 1.2. Решение

**MarineRadarSim** — программный тренажёр, который на обычном ПК воспроизводит:

* рабочее место оператора РЛС (внешний вид, органы управления, индикацию) — максимально близко к
  оригинальной системе (см. Q-001);
* радиолокационное изображение (ИКО), формируемое моделью РЛС: эхо-сигналы целей и берега, шумы,
  помехи от моря и осадков, тени, ограничение дальности горизонтом;
* функции САРП: захват и сопровождение целей, векторы, следы, ДКС/ВКС, ДПК/ВПК, тревоги,
  проигрывание манёвра;
* собственное судно и окружающие суда, движущиеся по сценарию;
* учебные задания с автоматической оценкой действий обучаемого.

## 1.3. Заинтересованные стороны

| Роль | Интерес |
|------|---------|
| Обучаемый (курсант) | Отработать навыки работы с РЛС/САРП без реальной аппаратуры |
| Преподаватель / методист | Создавать учебные сценарии, проверять результаты |
| Разработчик | Поддерживаемая, тестируемая кодовая база |
| Заказчик / учебное заведение | Соответствие программе подготовки (ПДНВ, модельные курсы IMO 1.07 / 1.08) |

## 1.4. Цели (измеримые)

| ID | Цель | Критерий |
|----|------|----------|
| G-1 | Реалистичный интерфейс | Преподаватель, работавший с оригиналом, подтверждает соответствие органов управления и индикации |
| G-2 | Правдоподобное изображение | Цели, берег, помехи моря/дождя, регулировки Усиление/ВОД/ДОЖДЬ дают визуально и качественно верный эффект |
| G-3 | Корректная математика САРП | ДКС/ВКС/ДПК/ВПК совпадают с эталонным расчётом (точные данные) с погрешностью ≤ 1 %; с шумом — в пределах допусков IEC 62388 |
| G-4 | Учебный процесс | Задание запускается, выполняется, оценивается и сохраняется без участия разработчика |
| G-5 | Автономность | Работает на ПК без сети, установка — копирование папки / один пакет |

## 1.5. Границы (Scope)

### Входит в продукт (MVP + последующие этапы)

* Одно рабочее место, один оператор, одно собственное судно.
* 2D-изображение ИКО (PPI), режимы ориентации и движения.
* Модель одной РЛС X-диапазона (S-диапазон — опционально, этап 2+).
* САРП: ручной и автоматический захват (в зоне охраны), сопровождение до 40 целей.
* Сценарии в YAML, результаты в JSON, журнал событий.
* Пауза / ускорение времени / сброс / запись и воспроизведение (replay).

### Не входит (явно)

* Сеть, сервер, многопользовательский режим, рабочее место инструктора по сети.
* БД, авторизация, Web UI.
* 3D-визуализация, «вид с мостика».
* Подключение к реальному оборудованию (NMEA, радар-интерфейсы).
* Полноценная гидродинамика судна (используется упрощённая модель манёвренности).
* Электронная карта (ЭКНИС) — только береговая линия как источник эха; наложение карты — кандидат на этап 3+.
* AIS — кандидат на этап 3+ (архитектура не должна этому препятствовать).

## 1.6. Принципы продукта

1. **Сначала поведение оригинала, потом красота.** Порядок действий и реакция системы важнее графики.
2. **Детерминизм.** Один сценарий + одно зерно ГСЧ + одни действия → один и тот же результат.
   Это основа для оценивания, разбора ошибок (replay) и тестов.
3. **Модель не зависит от UI.** Ядро симуляции запускается без Qt (headless) — в тестах и для проверки сценариев.
4. **Простота MVP.** Модульный монолит, файлы вместо БД, два потока.

## 1.7. Допущения

* Оригинальная система — судовая РЛС с САРП, интерфейс на русском языке (по надписям текущего макета:
  УСИЛЕНИЕ, ВОД/МВ, ДОЖДЬ, АПЧ, САРП, ДКС, ВКС, ДПК, ВПК). Модель/производитель уточняется (Q-001).
* Целевая платформа — Linux (Debian 12) и Windows 10/11, x86-64, обычный офисный ПК; целевой монитор — 1280×1024 (5:4).
* Документация оригинальной системы (руководство оператора) будет доступна команде (Q-002).
